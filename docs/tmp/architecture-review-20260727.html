调用方手动从自己的参数构造 dict——key 名和变量名完全重复，session_id 出现两次。接口宽度和 dict 构造代码一样长。

一个 TraceInput dataclass 封装可追踪的参数面。构造函数就是接口，没有 dict、没有重复。

问题

每个调用点都手动构造 {"kb_id": kb_id, ...} 从自己的参数。新增参数意味着要在 2+ 处更新 dict。session_id 重复了两次（dict key + 具名参数）。接口很浅——调用方知道太多 tracer 输入结构的细节。

方案

定义一个 @dataclass TraceInput，包含 kb_id、session_id、query 字段。start_trace 直接接收它。调用方只构造一次。dict 的映射关系只存在于 dataclass 的 __init__ 中。

收益
  • 局部性：映射关系只在一个类型中定义，而不是 N 个调用方
  • 杠杆：加一个字段→所有调用方自动获得
  • 接口缩小：start_trace(name, TraceInput) vs start_trace(name, dict, session_id=…)
  • 可测试性：TraceInput 是纯 dataclass，构造零成本
  • 删除测试：移除手动 dict 构造后，复杂度集中到一种类型

问题

Trace 生命周期管理（start_trace/end_trace）是横切关注点。它和 SSE 事件处理交织在 agent_service.py 中。同时 start_generation/end_generation 散落在 rag/stream.py 里。两层都直接调 Langfuse——同一个外部系统有两个接缝。

方案

创建一个 GraphExecutionAdapter，封装整个图执行生命周期——start trace、运行图、end trace、内部管理 generation spans。agent_service.py 调 adapter.execute() 并获取事件。stream_answer 不再直接调用 tracer。

收益
  • 局部性：所有 tracing 逻辑在一个接缝后，而不是两个层
  • 杠杆：替换适配器就能禁用/改变整个图的 tracing 方式
  • 接口缩小：stream_chat 减少 3 行 trace 样板代码
  • 可测试性：mock 一个适配器，不需要分别 patch start_trace 和 start_generation

3. 将 SSE 事件转换合并到一个模块

值得探索
src/services/agent_service.py:92-117,119-130 src/api/chat.py:159-176
改造前——SSE 解析分散在两层
api/chat.py _stream_rag_response： 解析 SSE 字符串 → 提取 tokens/sources
agent_service.py stream_chat：处理图事件 → 构建 SSE 字符串
src/utils/sse.py 6 个纯格式化函数（无解析）

三个层参与 SSE：工具层有纯格式化函数；agent_service 构建事件；api/chat 又把它们反解析回来。API 层有脆弱的字符串解析。

改造后——一个模块拥有 SSE 契约
api/chat.py 接收结构化事件，yield SSE 字符串
sse_event_stream 模块 图事件 → SSE 字符串；去重；引用提取

agent_service yield 结构化事件 dict；新模块负责所有 SSE 格式化。

一个模块完成图事件到 SSE 字符串的转换。API 层不再解析——只需 yield 字符串。AgentService 不再做格式化。

问题

agent_service.py yield 的是 SSE 格式化的字符串（sse_token()、sse_citation()），但 api/chat.py 又反解析同样的字符串（if event.startswith("event: token")）来提取数据。同一份数据先序列化再立即反序列化——脆弱的浅层三明治。

方案

让 agent_service.stream_chat yield 结构化 dict（如 {"type": "token", "data": "净利润"}）。在 src/rag/ 或 src/utils/ 下创建新的 SSEEventStream 模块，负责将这些 dict 转为 SSE 字符串。API 层委托给这个 SSE 模块。

收益
  • 局部性：所有 SSE 格式/解析知识在一个模块
  • 杠杆：新增事件类型→更新一个模块，不是两个
  • 接口缩小：agent_service yield 类型化 dict，而不是格式化字符串
  • 删除测试：删除 api/chat.py 的解析→SSE 模块仍然可用

AgentService.stream_chat 负责图生命周期、SSE 事件路由、状态初始化、降级处理——全部未经测试。唯一的测试（test_chat.py）mock 的是 rag_chain 属性，这个属性在 AgentService 上根本不存在，所以这个测试实际是死的。

Override AgentService._graph 为一个 mock 编译图，让它 yield 已知事件。测试 stream_chat 在每种场景下（正常、降级、空结果、异常）是否产生正确的 SSE 事件。注入 mock chat_manager 来验证历史调用。

  • 局部性：直接测模块的接口，不通过 HTTP
  • 杠杆：一个 mock graph 覆盖事件路由、去重、异常、降级
  • 删除测试：如果 mock graph 下测试通过，说明模块接口是充分的
  • 接缝：_graph 和 _chat_manager 本来就是可注入的——用起来

从这里开始：候选 1（trace 输入接口）

这是你的原始问题，零风险，改动最小，前后对比最清晰。一个 TraceInput dataclass（不到 10 行）就能消除 dict 样板代码、消除 session_id 重复，并为候选 2 的 tracing 改造建立模式基础。

之后候选 4（测试接缝）能消除最大风险——agent_service.py 目前的测试空白意味着事件路由或降级处理的 bug 只能在生产环境被发现。
