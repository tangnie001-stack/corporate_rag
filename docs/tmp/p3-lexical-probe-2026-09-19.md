# P3 词项命中探针（jieba + PG 全文检索 横向比较）

- 语料：176 个分块 / 5 个知识库
- 检索条数 k：30（= TOP_K_RETRIEVAL，上限 100）
- 探针词项数：30（n-gram 2..4，df ∈ [2, 0.1×N]）

> **仅供相对比较，不得作为质量基线或发布判据。**
> 176 分块属**小语料**，k=30 下命中集合规模有限，多数词项会**平凡通过**；探针的用途是在同一语料上横向比配置，**既不测排序质量也不测语义召回**。

## 口径说明（读表前必读）

- **词项来源**：从**原始正文**抽 CJK 连续段的 2..4 元 n-gram，不经任何分词器 —— 避免同一分词器既造索引又造标签的自我循环。
- **命中判据**：原始正文的字符串包含（`str.__contains__`），与分词器无关。
- **词项筛选**：`2 <= df <= 0.1×N`，剔除 df=1 的无从判断项与高频的平凡通过项；再按 `(df 升序, 词项)` 取最稀有的前若干项。**该取舍使词项偏向最难召回的一端，各臂命中率因此是偏保守（偏病态）的下界，不得读作平均检索质量。**
- **单库钉定**：每个词项被钉在「按 kb_id 排序、第一个含该词项的知识库」上，只在该单库内检索。多库语料下这会进一步压低命中率 —— 同样属于**使结果更病态**的取舍。
- **排序近乎不起作用**：本语料下探针词项全局 df 均落在下界 df=2，在钉定的单个库内只有极少数行含该词项，远小于 k=30。因此「是否命中」这一集合成员判据对排序不敏感；排序差异需候选集远大于 k 才能测出。

## 分组 A1：分词配置（唯一同口径对比：char-bm25 vs jieba-bm25）

两臂除**分词方式**外完全同口径：同 BM25Okapi、同词项集、同在每库全池上排序（不过滤候选）、同 k。

| 配置 | 命中数/总数 | 词项命中率 |
|---|---|---|
| char-bm25 | 30/30 | 1.0000 |
| jieba-bm25 | 29/30 | 0.9667 |

- 实测：`char-bm25` 30/30 = 1.0000；`jieba-bm25` 29/30 = 0.9667。
- 差值 = **1 个词项 = 3.33 个百分点**（n=30，每词项 1/30），方向是 **char 更高** —— 与「jieba 更好」相反，故**本次替换未观察到命中收益**。
- ⚠️ `char-bm25` 的满值属**构造性必然**：字符级索引以单字为单元，而探针查询 n-gram 逐字取自源文档，命中近乎必然。**1.0 不能证明「字符级检索质量更好」**；同理，也不能据此宣称 jieba 有收益。
- ⚠️ 由于排序近乎不起作用（见口径说明），该差值主要反映**候选集合成员**，而非排序质量。

## 分组 A2：混合变量行（仅供参考，**不可归因**）

以下两行相对 A1 **同时改了不止一个变量**，故不能与 A1 并列解读：

- `jieba-tsrank`：同时改了**候选生成**（先 `tsv @@ tsquery` 过滤，而非在每库全池上排序）与**打分**（`ts_rank`）。
- `pg-trgm`：同时改了**打分函数**（`similarity()`）与**切分单位**（trigram）。

| 配置 | 命中数/总数 | 词项命中率 |
|---|---|---|
| jieba-tsrank | 15/30 | 0.5000 |
| pg-trgm | 28/30 | 0.9333 |

- `jieba-tsrank` = 15/30 = 0.5000，相对 A1 的下降**主要由候选生成（tsquery 过滤）解释**：查询词元在该库的 tsv 里不存在时谓词直接为空，与分词把它切没切碎无关。**不可归因于分词质量。**
- `jieba-tsrank` 是生产落地形态（存储侧依赖 `scripts/rewrite_content_seg.py` 的重写结果）；`pg-trgm` 是本地唯一可对照的扩展方案，两者**都不构成对分词方案的证据**。

## 分组 B：查询构造（固定分词 = jieba，固定打分 = ts_rank）

| 配置 | 命中数/总数 | 词项命中率 |
|---|---|---|
| prefix-AND | 15/30 | 0.5000 |
| prefix-OR | 18/30 | 0.6000 |
| plainto-AND | 14/30 | 0.4667 |
| substring（定义性，非策略对比） | 30/30 | 1.0000 |

- `substring` = 30/30 = 1.0000 是**定义性**行（**恒为 1.0，非策略对比**）：`_term_kb` 已保证所选 kb 含该词项，且词项 df 远小于 k=30，故 `content LIKE '%term%' ... LIMIT k` **必然**返回全部含该词项的行 —— 命中是 WHERE 子句的同义反复。该行还是一次**无索引全表扫描且不排序**（`ORDER BY doc_id, chunk_index`），**不是可选策略，不得读作「LIKE 最好」**。
- `substring` 臂相对 `prefix-AND` **改了不止一个变量**：构造（`LIKE` vs `tsquery`）之外还改了排序（`ORDER BY doc_id, chunk_index` vs `ts_rank`）。
- `prefix-OR` vs `prefix-AND`：18/30 vs 15/30，差 **10.0 个百分点**。OR 是 AND 的**超集谓词**；在判据为「集合成员」而非「排序」、且候选集近饱和的口径下，这是**机械后果而非质量证据**。
- `plainto-AND` = 14/30 = 0.4667，低于 `prefix-AND` 3.3 个百分点，同样受「排序不敏感」影响。

## 分组 C：打分算法（固定 jieba + 前缀 AND）

| 配置 | 命中数/总数 | 词项命中率 |
|---|---|---|
| ts_rank | 15/30 | 0.5000 |
| ts_rank_cd | 15/30 | 0.5000 |

- 实测：`ts_rank` 15/30 = 0.5000；`ts_rank_cd` 15/30 = 0.5000。
- ⚠️ 零差不表示两个打分函数「同分」，而是：**候选集相同且规模 ≤ k 时，该口径对排序不敏感**，函数差异**在此口径下无法测出**（见口径说明）。要比较打分质量，需让候选集远大于 k 并比较 top-k 排序，本探针未做。

## 选型结论

- 查询构造：**prefix-AND**（分组 B 命中数/总数：prefix-AND = 15/30 / prefix-OR = 18/30 / plainto-AND = 14/30 / substring = 30/30（定义性））
- 打分算法：**ts_rank**（分组 C 命中数/总数：ts_rank = 15/30 / ts_rank_cd = 15/30）
- 分词方案：**jieba + `to_tsvector('simple')`**（分组 A1 命中数/总数：char-bm25 = 30/30 / jieba-bm25 = 29/30）

- **连接符不翻转**：`prefix-OR` 高出 `prefix-AND` 恰为 10.0 个百分点，判据字面是「**超过** 10 个百分点」，未触发；且 OR 是超集谓词、集合成员口径近饱和，+10pp 是机械后果而非质量证据。故保持 `_JOINER = " & "`。
- **打分函数不翻转**：分组 C 零差来自「该口径对排序不敏感」，非质量证据，故保持 `func.ts_rank(`。
