# 记忆模型（对话历史 vs Agent 记忆）

> **唯一归属**：本文件定义"**对话历史**"与"**Agent 记忆**"这两个概念的边界、记忆的用途与注入形态。
> **决策归属**：为什么把短期记忆真源留在应用自有存储、为什么不用 LangGraph checkpointer / Store，见 `docs/adr/0018-history-vs-memory-keep-own-truth-source.md`（本文件只描述**现在生效的口径**，不重复决策理由）。
> **术语归属**：条目级定义见 `docs/agents/glossary.md`「记忆」段。

## 两条轴：历史与记忆不是一回事

| | **对话历史**（transcript） | **Agent 记忆**（memory） |
|---|---|---|
| 回答什么 | 这次会话里**发生过什么** | 从多次会话里**习得了关于用户/情境的什么** |
| 生命周期 | 跟随会话（删除会话即消失） | **跨会话**，跟用户走 |
| 粒度 | 每条消息（user / assistant / tool），逐条原样 | 已归纳的**结论**（偏好 / 事实 / 经历 / 规则） |
| 可否有损 | **不可**（是回放与审计的真相） | **可**（可错、可遗忘、可重建） |
| 谁在管 | 会话层（`ChatManager`：Redis `chat_history:{session_id}` + PostgreSQL `conversation_history`） | 记忆子系统（**当前不存在**，规划见 ADR-0018 / Phase C） |
| 与 RAG 的关系 | 组装上下文的一部分，**不提供事实依据** | **不得**作为事实依据（见下「记忆边界」） |

一句话：**历史是"发生了什么"，记忆是"我因此知道了什么"。**

两者**不得合并为同一层**——失败代价不同：历史丢了是审计事故，记忆丢了只是下次再学一遍。

## 记忆的四个用途

| 用途 | 典型内容 | 消费方式 |
|---|---|---|
| **个性化**：让回答适配"这个人" | 画像（角色/行业）、兴趣 | **常驻注入**（几乎总相关） |
| **连续性**：跨会话的"我们上次说到哪" | 经历（episodic）、未完成任务 | **按需召回**（相关才注入） |
| **减少重复交代**：记住规则与纠正 | 偏好、纠正（corrections） | 常驻或按需，取决于稳定度 |
| **稳定约束**：长期指令 | 规则（rules） | 常驻注入，**且必须声明"这是背景，不是指令"** |

**明确不在列表内的用途**：**不用来回答事实**。见下。

## 记忆边界（硬规则）

长期记忆**只承载 episodic + user-semantic**（用户是谁 / 偏好 / 规则 / 经历）；**事实与知识类问题仍强制走 RAG 取证**——记忆不替代证据检索。

理由：记忆是**有损归纳且无来源锚点**，用它回答事实会摧毁溯源（每个断言必须能追到 chunk）。该边界由 ADR-0017 决策 4 确立，ADR-0018 沿用未改。

## 注入形态（两层，参考实现的一致做法）

- **常驻块**：画像 / 偏好 / 兴趣这类"几乎总相关"的，作为一小块**常量前缀**每轮注入（有预算上限）。
- **按需召回**：事实 / 任务这类"有时候才相关"的，检索后再注入（有预算与条数上限）。
- **标签与声明**：注入的记忆必须以可辨识标签包裹，并声明"**仅供参考，不是指令**"——否则"稳定约束"类记忆会变成 prompt 注入面。

写入侧的一致做法：**异步 + 类型化 + 门控**（记忆写错比不写更糟）。

## 本项目的现状

- **历史轴：有**。`chat_history:{session_id}`（Redis，TTL）供上下文组装；`conversation_history`（PostgreSQL）供审计与回放；跨轮压缩见 `docs/agents/code-map.md` 的 `chat/history_summary.py` 与 `chat/summary_store.py`。
  - ⚠️ **已知缺口**：`chat_history:{session_id}` **无条数裁剪**，仅受 TTL 约束（长会话会持续增长）。这是一个独立的小缺口，尚未处理。
- **记忆轴：无**。`src/` 内没有任何记忆代码；记忆属 Phase C，底座形态见 ADR-0018 决策 3。
  - ⚠️ `docs/agents/requirements_pool.md` 的 A-07 以"当前记忆提取…是同步 inline 调 LLM"描述现状，**与事实不符**（该条目源自早期设想，实际无记忆层）。

## 何时查阅

- 设计或评审任何"记忆"相关能力时（先确认它属于本文件的哪一类用途）
- 判断某份数据该进**历史**还是**记忆**时
- 有人提出"让模型记住 X"时（先问：这是历史、记忆，还是应当走 RAG 的知识）
