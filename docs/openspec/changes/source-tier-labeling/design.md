# Design: source-tier-labeling

## Context

引用质量问题的根因分析（本会话完成）：① 引用「支撑正确性」无系统验证——在线忠实度 judge 曾存在、因「需要判断的太多，影响对话质量」实战移除，LLM 裁决路线被否；② 引用「来源可信度」完全不透明——官网 PDF 与知乎帖对用户无差别。firecrawl-deep-research skill 的机制拆解（全文核实，无任何权威度数据文件）表明其可信度保障 = LLM 常识判断 + 透明呈现 + 读者终审；本地 4 个参考项目亦无现成域名分级数据。定案：**分级用确定性规则，判断的弹性留给模型，终审权交给用户**。设计稿：页面规格 `docs/design/pages/chat-citation-tier-2026-09-09.md` + 效果预览 `docs/design/chat-citation-tier-mockup-2026-09-09.html`（已登记进 MASTER.md 组件索引），徽标配色/降级规则以规格档为准。

## Goals / Non-Goals

**Goals**
- 来源权威等级确定性定档（规则表），全链路透传（context → 模型 → citation → 前端徽标）
- 模型被引导优先引用高等级来源（利用模型既有领域常识）
- 可信度透明化给用户（徽标），冲突数据如实呈现
- 候选规则信号：清单建立在行为统计 + 人工审核上，可持续成长

**Non-Goals**
- 不做检索期过滤/丢弃（信息损失风险，后置增强）
- 不做 LLM tier 判断（judge 实战否决，重蹈覆辙）
- 不做候选管理界面/定时任务（V1 用离线 SQL + cookbook 流程）
- 不解决「错标」（句子与来源的支撑关系）——本设计只管「来源可不可信」的透明化；错标目前仅有编号合法性校验 + 人工抽验，两个问题不混

## Decisions

### D1: 三层职责模型——定档/取舍/终审互不改写

- **规则表（确定性，管定档）**：命中清单定 T1-T4；未命中默认 T3；`.gov.cn`/`.edu.cn` 模式升 T1。模型判断**不改写**徽标——同一 URL 两次运行徽标一致（确定性，不随采样漂移）
- **模型（弹性，管取舍）**：context 块携带档位标注，模型结合问题上下文取舍——T1/T3 冲突优先 T1；T4 里的独家数据可降权引用。取舍自由完整，徽标不因此变化
- **用户（终审）**：徽标透明呈现，可信度判断的最后一环是人

### D2: 分级规则表数据 = 人工先验，const.py 起步

无外部数据集可接（firecrawl-workflows / 本地参考项目均核实无此数据；英文新闻可信度集领域语言不匹配）。种子清单（T1/T2/T4 各十几条）由 LLM 按领域常识批量拟候选 + 人工校对产出，落在 `const.py` 的 `SOURCE_TIER_RULES`；解析函数收敛为单函数 `resolve_source_tier(url, kind) -> int`（KB kind 直接返回 T0，不走域名）。未命中默认 T3（中性档，非差评）。后续清单扩到数百条需运营化时迁 MySQL 表（读取处已收敛，迁移成本低）。

**域名匹配语义**：规则域命中 = 域名精确相等，或域边界后缀匹配（`endswith("." + 规则域)`，保证 `evil-zhihu.com` 不命中 `zhihu.com`）；多条规则同时命中时**最长后缀优先**（`finance.sina.com.cn` 优先于 `sina.com.cn`）；匹配前归一化大小写、去 `www.` 前缀、剥路径/端口。

### D3: tier 透传方式——写进 context 块文本，不加新提示词

`RAGContext` 增加 `tier` 字段（语义见 D6）；`web_tools.py` 解析 url 计算 tier；返回给模型的 context 块文本追加档位标注（如 `[3] 来源: xxx (权威媒体)`）——模型在阅读检索结果时天然感知，无需新增系统提示段落。citation payload 携带 tier 落库，前端徽标据此渲染。

**标注落点（两处渲染点各自追加，格式统一「(档位标签)」括注，标签文案同源 const）**：KB 路径在 `to_prompt_text` 追加（`来源: xxx.pdf (第1页, 内部文档)`，标签并入页码括注）；web 路径在 `web_tools.py` 块文本手拼处追加（`[3] 来源: url (权威媒体)`）。`to_prompt_text` 与 RAGAS NLI 评估上下文共用（防漂移约定），故 NLI 上下文将随之包含档位标注——与时间锚点先例一致（NLI 看到的与模型看到的保持一致），RAGAS 评估对比需注意此改动为基线分界点，跨分界的 faithfulness 分数不可直接比。

### D6: tier 默认 None（未知），T0 仅显式产出

`RAGContext.tier` 默认 `None`（未定档），不设 T0 兜底默认——`RAGContext` 有 3 个构造点（retrieval / rag_tools / web_tools），若默认 T0，未来新增构造点漏传 tier 会静默把 web 来源标成最高信任档，错向且无告警。T0 只能由 `resolve_source_tier(url, kind=kb)` 显式产出，web 构造点显式调用解析函数；citation payload 中 `tier=null` 或缺省表示存量/未知，前端降级不显示徽标。

### D4: 候选规则信号——行为统计 + 人工闸门，V1 零新模块

**信号来源是引用行为数据，不是模型自我声明**（模型提名 = LLM 定档变体，否决）。V1 全离线：一条聚合 SQL 从 `conversation_history.sources` 提取**全部**域名并统计引用次数/跨会话数——「未命中清单过滤」不做进 SQL（避免 SQL 复刻 Python 解析逻辑、清单增补后 SQL 失真的双头维护），放到人工审核那步对照规则表人眼排除。过阈值（建议 ≥5 次且跨 ≥3 会话）输出候选；人工打开样本消息核对引用上下文 → 批准则 `SOURCE_TIER_RULES` 加行 + restart 生效，拒绝记 negative cache（**文档记录**：拒绝清单登记进 cookbook 附表，不建数据库表）防重复出现。后续演进（候选表 + 审核界面）为 YAGNI。

### D5: 非法编号观测信号

format_node 现有逻辑对超范围编号静默忽略（nodes.py:82）。补记 `retrieval_signal: signal=invalid_citation`（含编号值）——同一编号重复出现时聚合为一条（`ids` 为去重升序 pipe-join，`count` 为出现总次数，如 `[99]×2+[102]×1` → `ids="99|102" count=3`（`|` 非日志安全字符，值被引号包裹）），不做逐次日志防噪音；幻觉编号频率是模型退化的免费哨兵，零成本。

## Risks / Trade-offs

- [分级清单有主观性，长尾域名分级可能不准] → 透明徽标消化误判（用户看得见等级自己掂量）；候选信号 + 人工审核持续修正；未命中默认中性档不武断
- [模型对 tier 的取舍不受强制（可能仍引 T4）] → 接受：取舍是模型判断自由，徽标透明兜底；若观察到系统性偏好失衡，调提示词权重
- [Tavily 结果 url 可能是聚合页/跳转链接，域名≠内容真实来源] → 接受：tier 是启发式信号非承诺；后续可选增强 URL 归一化
- [citation payload 增加 tier 字段，存量消息无 tier] → 前端判空降级（不显示徽标），与 process 列兼容策略同构
- [to_prompt_text 含档位标注后 RAGAS NLI 上下文变化] → 接受：与时间锚点先例一致（NLI 与生产一致防漂移），基线分界点登记 cookbook（已定案 2026-09-09，并入 Task 7 文档步骤）
  - 后果 1——分数可比性断裂：change 落地前后的 faithfulness 不可直接比；落地日之后的评估为新基线，跨分界分数波动先想到格式变化而非质量退化
  - 后果 2——裁判可能被标注轻微带偏：「(权威媒体)」是给模型的引导元数据而非证据内容，NLI 严格只该看证据本身，信任标签可能造成微小打分偏移
  - 不接受的替代方案：让评估走一份不含标注的独立渲染——正是当年表格 faithfulness=0 误诊的双份漂移老路，两害相权 NLI 与生产一致优先
- [tier→中文标签 Python 与前端两处维护] → api_contract 登记权威映射表（tier → 标签文案），前端照抄；文档登记项已覆盖
  - 失效形态：Python 映射（context 块文本给模型看）与前端 JS 映射（徽标给用户看）各自一套，改一处忘另一处 → 模型上下文写「权威媒体」而用户徽标显示「普通来源」——不报错不崩，纯信息不一致且隐蔽
  - 缓解动线：改标签固定三步 const.py → api_contract.md → chat.html，走完才算改完
  - 放弃的替代方案：SSE payload 直接携带 label 字符串、前端只渲染——技术上根除漂移，但 payload 变胖、后端文案耦合前端展示；tier 集合小且稳定（5 值），文档闸门够用，真漂移再升级
- [规则表被运营频繁修改需发版] → 读取处收敛单函数，迁 MySQL 表成本低，待清单量级触发再迁

## Migration Plan

1. 代码落地（const 规则表 → RAGContext/web_tools → nodes 信号 → 前端徽标），`docker compose restart app` 生效
2. 种子清单初版由 LLM 拟候选 + 人工校对后定稿进 const.py
3. 回滚：revert 代码即可；citation 里多出的 tier 字段对旧前端无害（多余字段被忽略）
